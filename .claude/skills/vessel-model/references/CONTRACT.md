# The model contract: what binds by name, and what each shipped file's frame is

Measured 2026-10-17 on the seven live vessel files (`fbx_probe.py`, `part_map.py`, the prefab
YAML, the dossiers in `Docs/VesselModels/`). Re-measure before trusting a row: the artist files
were made by hand and each one is its own convention.

## 1. How a vessel prefab draws its model

`Assets/_Prefabs/Spacevessels/<Vessel>.prefab` nests the FBX as a **PrefabInstance**
(`m_SourcePrefab` = the FBX's guid). Everything the prefab touches inside the model is a
**stripped** component (`m_CorrespondingSourceObject: {fileID: <hash>, guid: <fbx>}`): the
SkinnedMeshRenderer (material overrides, `VesselAnimation.SkinnedMeshRenderer`,
`VesselCustomization._shipGeometries`), the Animator, the root bone, and the bone Transforms
that host jets, colliders, skimmers and FX (added as children with bone-space offsets).

Those hashes are generated by Unity's importer from **type + name** and nothing else you can
read (`fileIdsGeneration: 2`; `internalIDToNameTable` is empty on every vessel meta). Evidence
in the repo: the Squirrel's spliced FBX kept its mesh id across two exports of the same file
(Docs/claude/VESSEL_HUD_AND_ELEMENTS.md); the subdivided `Sparrow Missile.fbx` kept `Cube.003`
in place; renaming a node in ANOTHER file to borrow an id did not reproduce it (asset-surgery
SKILL.md, omni crystal, 2026-10). Therefore:

- **Same file path** (same guid) and **same node names** keep every stripped reference binding.
- A missing node does not error: the override becomes "unused" and the feature quietly does
  nothing (a jet with no host falls to the vessel origin).
- Keep the hierarchy too where a clip binds a bone PATH: the Animator binds clip curves by the
  bone's path under the animator root, so parent/child relationships of posed bones must stay.
  Reusing the shipped armature (`rig.import_shipped_armature`) keeps names, order, hierarchy
  and rest poses in one move.

## 2. The `.meta` keeps working iff

- `clipAnimations[]` entries pin `takeName -> internalID`: a take that keeps its name re-imports
  into the clip the controller references; a take missing from the file imports an empty clip;
  a take added gets no entry until someone opens the editor (Unity then adds it at a fresh id).
- `externalObjects` remaps FBX materials to `.mat` assets by **material name** (Squirrel:
  Domain/Body/Window; Dolphin: BASE.001/accent.001/windsheild.001). Keep the names; a slot the
  meta does not remap (Dolphin `N.001`) imports the embedded material and `FlareEngine` has no
  `_ColorMultiplier` to drive - a `.meta` edit fixes it, flag it.
- Import settings every vessel shares: `globalScale 1`, `useFileScale 1`, `animationType 2`
  (Generic), `importBlendShapes 1`, normals imported from the file (write split normals),
  `optimizeGameObjects 0`, `isReadable 1` (except SparrowModel4 / the two unwired rigs).
  `optimizeBones 1` strips a bone that skins nothing AND has no skinning descendants - keep hold
  bones as parents of skinning children (the Squirrel's `bbone_WholeWing.*` skin 0 verts and
  survive as parents).

| Manta rigs | accent | BASE | windsheild | N | - |

`ShipHelper.ApplyShipMaterial` paints the DOMAIN material into **slot 0 of a SkinnedMeshRenderer**
regardless of names (unless the prefab's `VesselCustomization._domainReplacesMaterials` names
materials, then by identity); `FlareBody` flashes slot 0, `FlareEngine` slot 3. So on the
Serpent and Sparrow the team colour lands on their `Body` slot - that is how they ship; keep
the order and the game keeps behaving. Every slot needs polygons or the exporter/importer drops
it and the array shifts.

## 4. Frames (the preset a spec declares)

| preset | files | GlobalSettings | root nodes | modelling frame after Blender import |
|---|---|---|---|---|
| `zup` | Squirrel, Sparrow | UnitScaleFactor 100 (metres), Up +Z, Front +Y, Coord -X | mesh node identity; armature carries the artist's own rotation | nose **-Y**, up +Z, pilot's left (.L bones) **+X** |
| `zup_identity` | Serpent | UnitScaleFactor 100, Up +Z, Front -Y, Coord +X | identity | the importer applies no turn: head/nose on **+Y**, up +Z, pilot's right +X |
| `yup` | Dolphin rig, Rhino rig | UnitScaleFactor 1 (cm), Up +Y, Front +Z, Coord +X | R(-90,0,0) S(100,100,100) on the mesh node AND the armature; vertices in metres under that scale | nose **-Y**, up +Z, .l bones **+X** |
| `yup_baked` | Manta rig, Urchin rig | as `yup` | mesh node IDENTITY with the centimetre data baked into the vertices (`bake_space_transform=True`); armature R(-90,0,0) S(100) | nose **-Y**, up +Z, .l bones **+X** |

Read the mesh node's TRS in `fbx_probe` before choosing between `yup` and `yup_baked`: both
import identically in Blender and Unity, but the prefab's colliders on the mesh node were
authored in that node's local frame, and the verify bounds check fails the wrong one by 100x.

Unity's result, measured against the prefabs' mounts: Z-up files land as Unity (x, y, z) =
(file x, file z, file y): nose +Z, the .L bones at -X = the pilot's left (the Squirrel's
`rollleft` take dips `.L`); Y-up files land nose +Z with X mirrored (Dolphin dossier 1.1). In
both cases **modelling in the Blender import frame and exporting with the matching preset
reproduces the shipped file's frame**, which is all the prefab needs. `rest_compare.py` on the
written file vs the shipped one is the proof (0.000 on all seven, 2026-10-17).

The Sparrow's armature node is scaled 0.2034 with a 180-degree Z turn; the Squirrel's armature
carries R(71.9, -180, 0): artists' scene scars. Reusing the imported armature object keeps them.

Direction convention (Squirrel dossier 3.5, closed): `pitchup` pitches the nose UP in Unity
(the driver writes `Pitch = -YSum`), `yawright` noses right, `rollleft` dips the `.L` wing.
Author poses about world axes in the Blender frame: pitch = X, roll = Y, yaw = Z; a tail at +Y
rotated by -X drops (nose up).

## 6. Morph magnitudes (the audit measures travel / mesh diagonal)

Shipped real shapes travel 2.5-17.9% of the diagonal; empty placeholders 0.000%. Aim 4-12%.
The in-editor audit reads Unity's skinned-mesh bounds (root-bone space) as the denominator, so
it reports 1.283x smaller than the offline probe on the Dolphin (VESSEL_CONSTRUCTION.md 4.5):
stay above 3% offline to stay above the audit's threshold.

Element meaning, fleet-wide: **Space** = reach/presence (extend), **Time** = rate/mobility
(sharpen, sweep, lengthen bells), **Charge** = threat/energy (the weapon grows), **Mass** =
size/volume (fatten the body). Map onto the vessel's own ability table
(`python3 Tools/Build/element_ability_table.py <Vessel>`) so the morph names what grew.
