# Card backgrounds — one per live mode, rendered from its own arena

`GameCard.UpdateCardView` does `BackgroundImage.sprite = game.CardBackground`, so a card's
backdrop is authored per mode on its own `SO_ArcadeGame`. Every PNG in this folder is a
**render of that mode's intensity-2 arena**, made offline from the arena's own data:

    python3 Tools/Build/render_card_backgrounds.py            # render all, import, rewire
    python3 Tools/Build/render_card_backgrounds.py Rampage    # one card
    python3 Tools/Build/render_card_backgrounds.py --check    # fail if any card is stale
    python3 Tools/Build/render_card_backgrounds.py --report   # where each card's geometry comes from

**Do not hand-edit or hand-replace these files** — `--check` re-renders and byte-compares, so a
hand edit reads as a stale card. The recipe for a mode lives in `render_card_backgrounds.py`, and
the `/cardart` skill says how to add one.

## Where the geometry comes from

| tier | meaning |
|---|---|
| **RUN** | the shipped environment generator is compiled and run (`Tools/Build/card_art_harness/`), with every field read off the prefab the mode's intensity-2 cell config names — what is drawn is what the arena lays, prism for prism |
| **COURSE** | a controller-built course generated by the shipped course generator at intensity 2 on the card's own fixed seed (a live match rolls its own, so the shape is representative) |
| **MODEL** | something that only exists once a match runs (a grown forest, a controller-built court) — the planting is measured the way `ModePreviewPlantingModel` measures it; each plant is a species glyph, because a grown plant's shape is emergent |
| **MONTAGE** | Maelstrom has no arena of its own, so its card is cut from the cards of the modes it can draw |

Pilots (a dart plus the prism trail it lays) and each mode's signature act (a Dolphin cone, a
bloom, a tracer, a creature in a cage) are STAGING, added so a card reads as a game rather than
as a level select.

## Hand captures still work

`author_card_backgrounds.py` imports any `<CardName>.png`/`.jpg` placed here and rewires the card
to it; naming is `<card asset name minus "ArcadeGame">`. A hand capture (the Screenshot Director,
`Docs/SCREENSHOT_DIRECTOR.md`, press **0**) will be overwritten the next time the renderer runs
for that card — so a mode that should ship a hand capture instead needs its row removed from the
renderer's roster, deliberately, rather than a file dropped on top.
