# Cosmic Shore Port — Progress Report (2026-07-10, pause point)

**What this is:** a faithful replication of Cosmic Shore onto a first-party
C#/.NET 10 stack. The Unity APIs the game code depends on are re-implemented in
a purpose-built engine layer (`CosmicShore.Engine`), and the game's own C# is
ported **verbatim** on top of it — same files, same names, same behavior, with
every necessary deviation from upstream source explicitly comment-tagged. The
goal set by the prompter: *"a foundation for excellence, not a proof of
concept"* — menu UI testable, multiple game modes playable, as close to the
Unity build as we can get.

**Where it lives:** everything is under `Port/` on branch
`claude/quirky-cannon-sk8a02` (nothing is ever merged outward). Loop memory /
full iteration history: `Port/PORT_PLAN.md` (62 logged iterations). Paused at
commit `8d03bc46`.

---

## What works today

A person can run the interactive client and play the full loop the milestone
asked for:

```
cd Port
dotnet run --project src/CosmicShore.Client -- --mode menushell
```

- **Real main menu** — the ported `ScreenSwitcher` slides between the real
  screens: HOME, STORE (browse + purchase captains/tickets against the local
  economy), PORT (leaderboards), HANGAR — plus the ARCADE modal family
  (explore view → game cards → configure modal with intensity/players/domain
  steppers).
- **Four playable domain minigames**, launched from that menu, played with
  mouse + keyboard (real READY button, Tab to cycle camera, human pilot or
  autopilot): **HexRace**, **Crystal Capture**, **Joust**, **AstroLeague** —
  through the real controllers, turn monitors, scoring, and end-game
  scoreboard, then back to the menu. **Tournament** chains modes headlessly.
- **Freestyle / lava-lamp** — the menu-behind-gameplay mode with cell ecology
  (flora, fauna, conserved-mass prisms) and the toybox (vessel changer, domain
  changer, painting toy's 4-station gallery).
- **Headless CLI** — every mode also runs deterministically without a window
  (`dotnet run --project src/CosmicShore.Cli -- hexrace --players 4 --seed 42`),
  which is what CI-grade verification is built on.

## How it's verified (the "gate" every iteration must pass)

- **1,712 tests green in both Debug and Release** (1,360 behavior tests over
  the ported game code + 352 ported/engine tests).
- **5 CLI modes** (hexrace, astroleague, joust, crystalcapture, tournament)
  exit 0 on fixed seeds.
- **11 canonical screenshot diagnostics** run under xvfb **twice per gate**:
  every diagnostic line must be byte-identical between runs, and the 11
  rendered PNGs have been **pixel-identical across the last 9 gates** — the
  whole sim + renderer is deterministic end to end.

## Fidelity discipline (what "verbatim" means here)

- Ported files carry upstream's code byte-for-byte where possible; every
  forced difference is a tagged `PORT Deviation (<arc>)` comment carrying the
  original source, so nothing is silently dropped and every deviation is
  greppable + reversible.
- Upstream quirks are **pinned by tests, not fixed** (e.g. the scoring
  accumulator's last-writer-wins semantics, `CaptainManager`'s OnDisable `+=`,
  the XP double-add through the captain-lookup alias) — the port replicates
  the game, it doesn't editorialize it.
- Upstream keeps moving and the port tracks it: three drift-syncs merged
  bleeding-edge and re-verified everything (`docs/DRIFT_*.txt`).

## How to reproduce the verification

```
cd Port
dotnet build -c Debug && dotnet build -c Release
dotnet test tests/CosmicShore.Tests  -c Debug   # 1360 green
dotnet test tests/CosmicShore.Tests.Ported -c Debug   # 352 green
# (same in Release)
for m in hexrace astroleague joust crystalcapture tournament; do
  dotnet run --project src/CosmicShore.Cli -c Debug -- $m --players 4 --seed 42
done
# windowed client (needs a display or xvfb-run):
dotnet run --project src/CosmicShore.Client -- --mode menushell
```
