# Cosmic Shore Port — Progress Report (2026-09-29)

The previous report (`PROGRESS_2026-07-10.md`) described a **hand-ported** game: 585 game files
re-typed onto a first-party engine, with its own client harness drawing approximations of the
menu. The work since then changed the approach. The port now runs **the real game**: the
unmodified `Assets/_Scripts` compile against the engine, and the real scenes, prefabs, materials,
shaders, meshes, fonts and sprites load from `Assets/`. It runs with no Unity install.

## What runs

```
export PATH=/opt/dotnet:$PATH
dotnet build Port/src/CosmicShore.Player -o <out>
COSMIC_SHORE_PROJECT=<repo root> dotnet <out>/CosmicShore.dll
```

- **Bootstrap → Authentication → Menu_Main.** The real `AppManager` DI root, the application
  state machine, the auth scene and the menu all run. Local lanes stand in for UGS: Cloud Save,
  Friends and Leaderboards persist to disk.
- **Menu_Main.** The real `ScreenSwitcher` screens, the arcade/arena/toy box hubs and the
  lava-lamp autopilot vessel. The world is Garland: flora and fauna grow through the real
  spawners, and prism mass is drawn through the real `PrismRenderService`.
- **An arcade launch.** Tested with Bloomrush: card → configure modal → READY → the host-driven
  scene load → countdown → flight with keyboard input, including the AI backfill.
- **A scripted driver for verification.** `--do "F:verb args"` supports click, move, type, key,
  hold, pad, inspect, ancestry, trails, renderers, `eval Type.Member` and `blast N`. It works with
  `--shot F:path`, `--render-from F` and `--frames N`, and runs under xvfb or headless.

## Verification

- `tests/CosmicShore.Tests` has 1,504 tests and `tests/CosmicShore.Tests.Ported` has 352. Both
  are green.
- Visual checks are scripted runs with screenshots: menu (Debug and Release), Bloomrush flight,
  blast sequence.
- Windowed runs log **0 errors**. The one exception is `Squad..ctor`, which is faithful: the
  game's own `AllCaptains` list is empty. `--headless` has no compute support, so
  `PrismRenderService` stands down and the game's strict `[PrismClock]` diagnostics fire. That is
  exactly what a Unity `-nographics` run does.

## Known gaps, in rough priority order

1. **Networking over the internet.** Sessions are discovered through a shared directory
   (`COSMIC_SHORE_NET_DIR`, a local or network folder), so a party spans machines on one LAN, not
   the internet; UGS itself is not reached. Netcode's delta compression and unreliable channels are
   not modelled: everything travels reliable-ordered over TCP.
2. **Per-frame CPU on very large worlds.** Measured on Bloomrush at its heaviest intensity
   (Rampage's forest), scripted at 60 steps/s, simulation only:

   | frame | before | after |
   |---|---|---|
   | 2370 (menu → match) | 5.8 ms | 1.1 ms |
   | 3570 | 84.6 ms | 19–26 ms |
   | 4170 | 176.8 ms | 34–47 ms |
   | 4470 | 304.6 ms | 45–65 ms |

   What changed in the engine: each frame phase walks only the scripts that declare that hook
   (it walked every behaviour for Update, LateUpdate and every fixed step); trigger-collider
   registration and coroutine stops are O(1) (both scanned every live entry — every prism a
   pool reset stops its coroutines, and there are ~40k); destroys de-duplicate through a set;
   `activeInHierarchy` is memoised against a hierarchy epoch. `COSMIC_SHORE_RENDER_TIMING=1` now
   prints the per-phase split and GC activity with each `[tick]` line; `CS_PORT_TRACE_CO`,
   `CS_PORT_TRACE_ANIM` and `CS_PORT_TRACE_RENDERERS` print the coroutine, animator and renderer
   censuses. What remains is mostly the game's own work: by frame 4200 ~40k prisms are waiting on
   `Prism.CreateBlockCoroutine`'s creation budget (6 completions a frame) and each spins a
   coroutine every frame, flora growth costs ~8 ms, and 285 heart crystals each animate 310
   bindings. A Unity build runs the same code; this is a finding about the game rather than the
   port, recorded here because the port is where it could be measured.

   The render collect was the other half: at the same frames the scene holds ~230k live
   renderers (~160k of them cactus spindles) to draw ~25k instances, and walking all of them
   cost ~150 ms. It now keeps a flat slot table of cached world bounding spheres, rebuilt only
   for renderers the engine reports changed (`Renderer.TrackChanges`: a transform write marks
   its subtree once per epoch, a reparent does the same, a material or mesh assignment marks its
   own renderer; `localRotation` became a property so its writes can report). Only renderers
   whose sphere is in the frustum are touched, and enabled/layer/activity are still tested on
   those, so they can never go stale. Collect is **40-53 ms** (renderer walk 20-29 ms, from
   ~145 ms). `COSMIC_SHORE_VERIFY_CULL=1` compares the slotted result with the full walk every
   30 frames: 0 differences over late Bloomrush and 50 menu checks. `COSMIC_SHORE_SLOW_COLLECT=1`
   restores the old walk. Instance writes and uploads went from 50-130 ms to **16-19 ms** at
   ~25k instances: the whole draw is now one read-only transform pass (it ended after the
   collect, so every instance write re-walked its parent chain), and
   `Renderer.HasPropertyBlock()` no longer mints and copies a property block per call, which
   also took rendered-frame GC from ~77 gen-0 collections per 30 frames to 2. The ECS hand-over
   went from ~20 ms to **~4 ms** for ~11k entities: each entity's resolved draw is cached on its
   record against (shape, value version, mesh/material registry version), and every component
   value write bumps the value version (`COSMIC_SHORE_VERIFY_ENTITIES=1` re-resolves every cache
   hit every 30 frames: 0 stale). Collect as a whole is **22-26 ms**, from ~150 ms.

   The ECS store itself (components boxed in a dictionary per entity) is unchanged; with the
   hand-over cached it no longer costs a rendered frame much, so the packed archetype layout
   is no longer on the critical path.

3. *(Resolved.)* **Both view-dependent prism effects are verified on screen.** The vessel vision
   band (`docs/vision_band_check.png`): a Ruby AI Manta staged ahead of the camera renders
   unmarked at 100 u, ramps in at 250 u, is a flat signal-colour silhouette at 900 u, is fading at
   2600 u and is gone at 4000 u. The Urchin cradle drape (`docs/cradle_check.png`): with the world

   stand-in hull reported through the game's own `PrismCradle.Publish` (`cradle 2.5`) swaps the
   prism to the high-poly mesh and the face closes smoothly over the hull, with continuous

## Rules the port keeps

- Nothing under `Assets/` is modified. The port reads the project and nothing else.
- No Unity or third-party source is copied. Behaviour is implemented from documented contracts.
  First-party shaders and graphs are translated.
- GLSL sources must be ASCII. The driver is handed a character count, so a multi-byte character
  truncates the source. `GlProgram` rejects a non-ASCII source up front.
