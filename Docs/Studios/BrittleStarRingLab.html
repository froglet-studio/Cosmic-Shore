Why it went dark in Unity

  1. While the ring turns more than 1.5° a frame, BrittleStarAnimation hides the hull's own ring and hands it to BrittleStarRingSmearPass. The pass first redraws the ring into a layer with the hull's materials, then averages that layer over the frame's turn.
  2. To redraw each material, ForwardPass looks for a pass tagged UniversalForward, UniversalForwardOnly or SRPDefaultUnlit. The hull wears VesselGraph, an Unlit Shader Graph, and URP 17.3 writes that graph's forward pass with no LightMode tag (UniversalUnlitSubTarget sets none and the generator writes // LightMode: <None>). No pass matched, so the layer stayed empty, the smear averaged nothing, and the ring was gone.
  3. The safety net missed it. A smear counts as drawn as soon as its pass is recorded, not when anything lands in the layer, so the hull never got its ring back.
  4. The port was never compiled or run before merge (no .NET or editor in that session). The checklist's step 3 is where it showed.

The lab could not have caught a port bug. It could have shown the right look, though: round 2 drew a stand-in ring and only measured total light. Round 3 renders the shipped mesh and post, and its Brightest plates kept column puts today's build at about 6% the moment the ring turns (what is left is the hull core's glow).

What changes in Unity

  • The fix, needed whichever look wins (branch claude/brittlestar-smear-empty-layer): ForwardPass takes the first untagged pass when no tagged forward pass exists, which is how URP draws it. A smear whose layer would be empty is skipped and never counted as drawn, so the hull keeps its own ring. BrittleStarRingSpinTests checks that every hull material has a pass to draw with.
  • Averaged smear (shipped): no further change.
  • No smear: ringSmear 0 in BrittleStarConfig.asset. One number. At 30 fps a ring at the cap turns 36° a frame, half a turret spacing, where the eye can no longer tell which way it turns.
  • Peak-hold smear: in BrittleStarRingSmear.shader, each pixel keeps its brightest copy and only the coverage is averaged: peak = max(peak, s.rgb); cover += s.a;, then return half4(peak, cover / count);. Also ringSmearStepDegrees 2.5 → 1.25 and ringSmearMaxCopies 24 → 32, so thin plates don't break into dashes.
  • Afterimage: the same pass with copies placed back over the last few milliseconds of the ring's turn instead of one frame. Each weighs start × (1 − age)^1.5, and the ring as it stands is drawn over the brightest of them. BrittleStarAnimation keeps about 0.1 s of drawn phases, and the shader takes a weight per copy.

Check the game look against the editor

  1. With the fix in, pick the colour set and domain you fly. Nocturne Jade is the default.
  2. Set Framing to 1:1 at 1080p and the Game view to 1920×1080. The ring should be the same size, about 300 px across.
  3. Set Game frame rate to what the editor's Stats panel shows and spin the stick at about 3 rev/s. The averaged smear scope should match the editor. If it doesn't, say what differs and the lab gets fixed before anyone picks.
  4. In the Frame Debugger during a spin, BrittleStar ring layer should hold one draw per ring submesh.

Not modelled: the scene's own skybox (a SkyColor field with a faint nebula and stars stands in), the Panini projection (0.7), element morphs, the camera's motion, trails and other ships, and plume flicker. Unity's smear layer is single-sample; this page renders it with 4× MSAA like the rest of the frame.
