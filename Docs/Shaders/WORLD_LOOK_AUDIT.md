## How an effect is found, and what is left out

- A prefab is an effect when it has a ParticleSystem, TrailRenderer, LineRenderer or VisualEffect, or a MeshRenderer / SkinnedMeshRenderer whose material's shader name says Unlit, Particles, Additive, Sprites or UI, or whose folder or file name says one of: fx, effect, impact, explosion, blast, trail, petal, bloom, beam, lance, ring, shield, wormhole, tunnel, crystal (and the kin: projectile, missile, bomb, burst, spark, crackle, laser, boost, jet, lightning, ripple, shockwave, halo, glow, flare).
- On a prefab found by its name every world renderer is part of the effect; on one found by a particle, trail, line or unlit material only those renderers are (a vessel's hull is not an effect because the vessel carries a particle burst).
- Anything under a Canvas in screen space (Overlay or Camera) is UI and left out; the one exception is a world renderer inside such a canvas named like a ring, radius or reticle, which is the `screen-ring` shape the second rule forbids.
- A nested FBX model instance is listed with the materials its instance overrides; its importer materials are not readable here.
- Lit or unlit is read from the shader: the name (Unlit, Particles/Unlit, Sprites, UI), a Shader Graph's sub-target and whether any node (or a custom function's HLSL, or a sub graph) reads a normal or a light, and a .shader's lighting code. Every project graph in this tree sits on the Unlit sub-target and shades itself: the node check is what tells a prism graph (reads Normal Vector) from a flat fill.
