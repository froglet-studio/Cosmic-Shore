# Asset gaps — measuring them, and turning them into tasks nobody has to remember to file

**Status: the measurement layer is built and running (§3). The distribution layer (§4) and the
anticipation layer (§5) are a PROPOSAL awaiting the decisions in §8.** Nothing in this document
writes to Notion, GitHub or Unity yet.

---

## 1. The problem, stated precisely

The project is very good at recording that an asset is missing, and has no mechanism at all for
turning that record into work somebody does.

The recording convention is deliberate and it is good. CLAUDE.md's audio rule says an unauthored
sound ships as an **empty `EventReference` in the inspector**, never a borrowed "temp" event,
precisely *because* an empty slot is a visible TODO and a temp event is an invisible one. The same
shape repeats for art: a card with no icon, a prism with no skim burst, an ability with no sound
field at all.

So the to-do list already exists, written in the assets. What is missing is every step after that:

| Step | Today |
|---|---|
| Find every empty slot | Nobody can. There is no inventory — a grep finds the ones it knows to look for |
| Group them into work worth assigning | Hand-written, when someone remembers (`Docs/AudioSystem/CHARLES_TASKS.md`, nine items, authored once) |
| Get them to the person who fills them | A human notices and writes a Notion row |
| Know when one is filled | Nobody. `CHARLES_TASKS.md` cannot tell you which of its nine are done |
| Catch a NEW gap the day it is created | Nothing. A new ability ships silent and the branch merges green |

The cost of that last row is the one that compounds: **every feature that lands adds slots, and
none of them announce themselves.** The Manta's sting bomb bay shipped with six named sound slots
and six silences, in a branch whose PR body says nothing about audio, because there was nothing to
say it to.

And the cost is not only the un-filled slot. Measured below: **13 finished FMOD events are authored
in the project and referenced by nothing**, while slots that those very events would fill sit
empty. `event:/SFX/Loops/Space Tadpole` exists; the Space tadpole's loop slot is empty. The work was
done and the two lists never met.

## 2. What is actually missing, measured today

Run `python3 Tools/Build/asset_gap_census.py` and `python3 Tools/Build/check_fmod_event_references.py`.
As of this branch:

| | count |
|---|---|
| Asset slots declared (sound auto-discovered + art/VFX registered) | **74** |
| Slot instances across every prefab, scene and SO | **1,502** |
| Wired | 1,389 |
| **Gaps** | **69** — Sound 53 · 2D graphics 12 · VFX 4 |
| Abilities with no sound slot at all (against CLAUDE.md's per-ability rule) | **16** |
| Wired slots whose FMOD GUID no longer resolves | **0** — the wiring is healthy |
| Wired slots whose cached path string disagrees with the event's real path | **7** |
| FMOD events authored and referenced by nothing | **13** |

The gap list in full is `GAP_CENSUS.md`, regenerated by the tool. The shape of it:

- **18 · `IconEmitter`** — the currency-burst fire/land pair, on 3 live Menu_Main emitters and 6
  copies inside the migration prefabs. One sound, nine sites. (`CHARLES_TASKS.md` C9.)
- **12 · arcade / vessel card art** — Astro League, Scarab Scramble and Tollway have no icon and no
  card background; Cosmic Drift and Shooting Gallery have no background; the Scarab has no hangar
  preview image.
- **6 · Manta sting bomb bay** — armed, planted, fuse expired, kabloom, cascade bloom, skim charge.
- **4 · VFX** — the prism skim burst on the ring, pentagon and (waived) menu trail prisms.
- **3 · `AudioSystem`** — `driftStartEvent`, `driftEndEvent`, `creatureBlockHitEvent` (C3).
- **3 · profile name typing tick**, **2 · Urchin spike charge**, **1 each** Urchin track deploy,
  Scarab juke whoosh, countdown beat, two tadpole loops.

Two findings from that list are worth more than the list itself:

**(a) A gap is per SITE, not per slot.** The countdown beat is one sound and **28 component
instances** — the prefab plus a scene-local copy in 27 game scenes. Wiring the prefab fixes one of
them. Any process that tracks "the countdown needs a sound" as one item and then calls it done is
wrong on 27 counts.

**(b) The FMOD project already answers some of these.** Of the 13 orphan events,
`SFX/Loops/Space Tadpole` matches an empty tadpole loop slot, `SFX/Loops/Drift sparrow` matches the
unwired drift pair, and `SFX/Loops/Boost Activate 2` is plausibly the fix for C2 (the boost event
that loops and is fired as a one-shot, so boost is silent). **Some of the backlog is a wiring task,
not an authoring task** — and nothing in the project could tell you which until now.

## 3. Layer 1 — DETECT (built)

Two readers. Neither writes anything under `Assets/`.

### `Tools/Build/asset_gap_census.py`

Answers *which declared slots are unfilled*. Sound slots are **discovered from the C#** (every
serialized `EventReference`), because the convention makes every one of them a slot by
construction. Visual and art slots are **declared** in `Tools/Build/asset_slot_registry.json`,
because a null `GameObject` or `Sprite` field is usually optional and only a human can say which
ones a discipline owes.

Per slot instance it reports `wired` · `wired-by-override` · `empty` · `silent` · `nulled` ·
`not-required` · `waived` · `ambiguous`, and writes `census.json` (machine) + `GAP_CENSUS.md`
(human). `--check` fails against `baseline.json`; `--self-test` is its own negative control.

Four things it has to get right, each of which produced a wrong answer before it did:

- **A slot's value lives in one of three places.** On the asset; as a scene or nested-prefab
  instance **override**; or **nowhere at all** — a field added to the C# after an asset was last
  saved is absent from that asset's YAML, and the runtime value is then the field initialiser. All
  50 of `AudioSystem`'s event slots are in the third category on the prefab and the second in
  `Bootstrap.unity`; all six Manta sting slots are in the third. A census that reads only the asset
  reports the first as 50 gaps and the second as zero.
- **A scene's component STUB is not a component.** A prefab instance contributes a `stripped` 114
  document carrying the script guid and none of the fields. Counting those as instances invented
  **52 phantom AudioSystem gaps** — every one of them wired by overrides in the same file. 451 such
  stubs are skipped.
- **Unity's serialization rule has to be applied literally, not approximated.** A naive field
  pattern also matches an expression-bodied property (`public EventReference Foo => foo;` — this
  duplicated all six Manta slots), a method parameter, and a local variable. All three are pinned
  as negative controls in `--self-test`.
- **A multi-line attribute breaks a line-shape parse.** `[SerializeField, Tooltip("…" + "…")]`
  spans lines that neither open nor close a bracket, so walking upward by line shape concludes
  there is no `[SerializeField]` and silently drops a real slot — which is what happened to
  `ShipAudioController.additionalEngineLayers`. The attribute block is delimited by the previous
  statement terminator instead.

Known limits, stated rather than hidden: it reads YAML, not Unity's object model, so a value
arriving through a **nested prefab variant chain deeper than one level** is not resolved; a slot
that is a **list** (`EventReference[]`) is reported as an unsupported shape rather than read as one
slot; and art coverage is exactly what the registry claims and nothing more.

### `Tools/Build/check_fmod_event_references.py`

Answers the questions about the slots that are **full**, against the in-repo FMOD Studio project
(`Cosmic Shore/Metadata/Event/*.xml`, 71 events): **dangling** (points at a GUID no event carries —
silent at runtime with a plausible path still showing), **drift** (GUID resolves, cached path string
disagrees — harmless to FMOD, and every human and tool reads that string), and **orphan** (an event
nothing references).

The serialized GUID layout is not documented and not guessable — Data1 big-endian, Data2 big-endian
with its 16-bit halves swapped, Data3/Data4 little-endian — so `--self-test` pins it against a known
pair from this repo. A future FMODUnity upgrade that changes the packing then fails loudly instead
of reporting all 70 slots as dangling.

## 4. Layer 2 — DISTRIBUTE (proposed)

**The precedent already exists and works: `/qa-backlog`.** It scans merges for untested work, keeps
a generated, prioritised, self-contained list in `Docs/QA/`, applies submitted results
deterministically through a script, archives what passed and opens dev tasks for what failed. This
proposal is the same loop with a different input, and with one advantage QA does not have: **the
evidence is in the repository, so closure needs no human report.** A filled slot closes its own
task on the next run.

```
  a branch adds an ability / a card / a species
            │
            ▼
  asset_gap_census.py            ← CI, and on demand
            │  census.json  (stable per-gap IDs)
            ▼
  /asset-gaps  skill             ← groups gaps into TASKS, writes Docs/ASSET_GAPS/TASKS.md,
            │                      syncs one row per task into Notion, closes rows whose
            │                      gaps are gone
            ▼
  Notion: Jog Builds Table 2026  ← Type = "Haptic/Sound/Visual FX" | "2D graphics",
            │                      Status Open → Done, Priority, Milestone, assignee
            ▼
  the person fills the slot in FMOD / Unity
            │
            ▼
  next census run: the gap ID is gone → the skill flips the row to Done
```

### The task, not the slot

One Notion row per **group**, not per gap. The census already groups (`sound:IconEmitter`,
`art2d:arcade-card`), and the group is what a person can actually do in one sitting: *author the
currency-burst pair and wire it to all nine emitters*. Each row's body carries the full site list as
checkboxes, so finding (a) above — a gap is per site — survives into the task.

Row contents, all derivable, none hand-written:

- **Title** — `[SFX] Currency burst — fire + land (9 sites)`
- **Type** — the census `discipline`, which is already spelled to match the Notion `Type` options
- **Body** — what the sound/art is for, where each site is, the convention note (empty means
  unauthored, never substitute a temp event), and any orphan FMOD event that looks like the answer
- **Task ID** — `AG-<kind>-<group>`, stable across runs, stored in the row so the sync is
  idempotent. Same discipline as `QA-<AREA>-<SLUG>` and the Bug Ledger's signature-derived ids

### Closing without bookkeeping

The census's per-gap ID is `kind:Class.field@asset#docId`. A row is Done when **none** of its gap
IDs is in the current census. That is the whole closure rule: no status meetings, no "is this done
yet", and no way for a filled slot to keep generating a task. The inverse also holds — a row that
was Done and whose gap comes back (an asset reverted, a prefab re-saved) is re-opened as a
regression, exactly as the Bug Ledger re-opens a signature.

### Where it runs

- **CI, on every PR** — `asset_gap_census.py --check` against the baseline, beside the eight checks
  `unity-ci.yml` already runs. A NEW gap fails the branch that introduced it, with the offending
  class, field and asset named. This is the half that makes the system self-maintaining: you cannot
  add an ability with no sound field and merge green.
- **Weekly, unattended** — a Claude Code Remote Routine re-runs the census, syncs Notion, and posts
  the delta (opened, closed, still open). No human triggers it.
- **In the editor** — `FrogletTools ▸ Validation ▸ Asset Gaps`, a READER per `Docs/TOOLING.md` §6,
  showing the same list where an artist or audio owner actually works, with a "ping" button per row
  and a click-through to the offending asset.

## 5. Layer 3 — ANTICIPATE (proposed)

Templates alone do not generate tasks — the user's framing is exactly right. What makes a template
useful here is that **the registry is the contract between a template and the census**: a template
that adds a slot adds a registry row in the same commit, and from that moment the slot is tracked
whether or not anyone remembers it exists.

Three places to apply that:

1. **Unity-side generators.** The project already generates modes, vessels, icons and preview
   assets (`Tools/Build/author_*.py`, the FrogletTools authoring windows). A generator that creates
   an `SO_ArcadeGame` should emit the card-art registry rows with it; a new ability executor
   scaffold should carry its `[SerializeField] EventReference` stubs. The slot then exists, empty
   and tracked, from the first commit — which is the state the audio convention already asks for.
2. **The `/vessel` and mode skills.** Both already carry per-subsystem checklists. Add one line to
   each: *a new ability declares its own sound slot; a new card declares its art rows.* The census
   enforces it, so the checklist line is a reminder rather than the mechanism.
3. **Notion templates.** A task template per discipline so a row created by hand looks like a row
   created by the sync — same fields, same ID convention — and the two do not diverge into a
   hand-list and a robot-list.

## 6. What this deliberately does NOT do

- **It does not judge quality.** It knows a slot is filled, not that the sound is good. Taste stays
  with the person; the machine tracks presence.
- **It does not author anything.** No placeholder assets, no temp events. That is the convention
  this whole system exists to serve.
- **It does not replace `CHARLES_TASKS.md`.** That file carries FMOD-project work with no slot in
  Unity at all (bus→VCA routing, max-instance limits, channel counts, a loop region on a one-shot
  event). Those are real tasks that no census can see, because the evidence is inside the `.fspro`.
  §4's sync should link to it, not absorb it.
- **It does not gate the build on an EXISTING gap.** The baseline exists so the 69 known gaps do not
  block every PR; only a *new* gap fails. A gap leaves the baseline by being filled or by being
  waived with a reason.

## 8. Decisions needed before phase 2

1. **Notion target.** `Jog Builds Table 2026` (`Type` already carries *Haptic/Sound/Visual FX*,
   *2D graphics*, *Theme/Colors/Music*; `Status`, `Priority`, `Milestone`, `assignee`, `Project`) —
   or a dedicated Asset Pipeline database? The Jog table means these tasks live where the team
   already looks; a separate database means the sync can own every row in it without touching
   hand-written ones.
2. **Who gets assigned.** Per discipline (all Sound → the audio owner) or left unassigned for
   triage?
3. **Milestone / priority policy.** Does a gap default to the current jog, or to `Vlater` until
   somebody pulls it?
4. **How hard the CI gate bites.** Recommended: fail on a new gap, with `--write-baseline` as the
   documented escape hatch and a waiver (with a reason) as the preferred one.
5. **Registry ownership.** Engineering adds rows as slots are created; who reviews that the art
   list is complete?
