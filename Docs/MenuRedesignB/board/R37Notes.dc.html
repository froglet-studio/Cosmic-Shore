Rev 37 notes - connection states and rejoin
Asked. "Where are the others like the connection lost and reconnect ones?" and "If someone leaves a game and then they boot up while the game is running the game should ask the user if they want to rejoin that game."
Built already (section 100.2). Lost, Reconnecting and Back online are the DisconnectNoticeView built from the boot Retry window; these boards show them for the first time. Every word is in DisconnectNoticeConfig.
New. Dropped out of a match: a guest whose link breaks lands back on their own Home while an AI pilot takes their vessel on the host (the game does both today); this window says so and offers REJOIN. The host left: one honest line and BACK TO HOME (the host is a player, so the match ends with them; no rejoin). Rejoin on boot: after sign-in, if the match you left is still running, Home opens with the mode's card, who is in it, REJOIN (lime, A, selected) and NOT NOW (B).
Rules. Lime only on the one action that puts you back (Reconnect, Rejoin); nothing red, because losing a connection is not the player's fault. A pad lands on the lime button; B always means 'not now'. If the match ends while the window is up, it turns into 'The match moved on' with BACK TO HOME.
For the build. The client remembers the match it is in (session id, mode); on boot it asks presence whether a party mate still advertises that match; REJOIN joins by session id with a rejoin token, and the host hands the AI-flown vessel back to the returning player instead of spawning a second one. Section 103 has the details.
