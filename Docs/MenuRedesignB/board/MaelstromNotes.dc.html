Maelstrom in-game UI
Three screens, kept
HUB between rounds (top bar, the round cards, a live preview of the next round, READY with the tally and the 30 s / 3 s countdown), STATS once the tournament is decided (NEXT, no countdown, the last arena in the preview), and the SUMMARY (winning domain, domain ranking, a card per pilot, Play Again for the host, Main Menu for everyone, STATS back to screen 2). MaelstromSceneView keeps binding everything by name, so the rebuild is a re-skin of the same objects.
Every value, kept
Game pool (n of m modes, intensity), round status (Round n / n rounds played), the win target line, leading domain, per-round winner, each pilot's round score and running total, the ready tally, the countdown, the summary's GAME WON / GAME OVER, the domain rank and each pilot's total.
What changes
ROUND INDEX : 3 / ROUND NAME : SLINGSHOT become a Round 3 eyebrow over the mode name on the mode's own card art. Scores are a two-column table (ROUND, TOTAL) under avatars ringed in each pilot's domain. A new Race to 12 strip draws each domain's points against the target (computed from the same tournament data the leading-domain line reads). Ready shows each pilot's avatar ticking ready, as the in-game Ready plate does.
Motion
Cards rise in one stagger apart; the standings bars grow; the next round's card carries the Control Active outline; a pilot readying ticks (punch); the summary's winner line reveals, the rule grows, the cards rise in order of rank.
Pad
The round cards scroll on LB / RB (or the stick), A readies / NEXT, on the summary A Play Again (host), Y Stats, B Main Menu.
Built 2026-10-15 (section 27)
Hub, stats and summary are built in Unity (Tools/Build/author_maelstrom_ui.py); the three card prefabs are regenerated in place. The Race to N strip is built. A non-host sees no Play Again, as before. Pilots ready shows the human pilots only: an AI has no button to press. The ROUND column is the points the round paid the domain; the mode's own score sits under each name.
