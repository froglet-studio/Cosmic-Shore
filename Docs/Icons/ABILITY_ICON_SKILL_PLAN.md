# Plan: an `/ability-icon` skill (the 2D twin of `/vessel-model`)

Garrett, 2026-10-24: "you have recently updated your skills to make 3d models. Now lets do the same
for your ability to illustrate 2d assets ... specifically ... new icons for the vessel's elemental
abilities ... the current icons range from decent to terrible. Look over our icons and come up with a
plan for making a skill that enables you to make better icons in the future."

This is the plan. Nothing in `Assets/` changes with it. The audit sheet it was written from is
`Docs/Icons/ability_icons_audit_2026-10-24.png` (every ability icon in the tree, tinted on the HUD
navy at 128 px, plus the artist-drawn Sparrow / Squirrel / Dolphin HUD icons at the end) and
`..._40px.png` (the same icons at 40 px, close to the 60 px box the lockup draws them in).

## 1. What exists today (measured)

**55 ability icons** under `Assets/_Graphics/Icons/AbilityIcons/<Hull>/`, 128 x 128, pure white in
RGB with the shape in alpha, multiply-tinted at runtime by the four-icon row and drawn in a **60 px
box** (`AbilityLockupStyleSO.iconBoxSize`; the element flower above is 44 px). 11 of them are named
`*-PLACEHOLDER.png` (Rhino 4, Scarab 4, Serpent 3). All 55 are generated by **twelve separate
Python scripts** in `Tools/Build/` (`author_<hull>_icons.py`, `author_<hull>_icon_placeholders.py`,
`author_hull_icon_placeholders.py`), each with its own `--check` drift gate and deterministic guids.

The scripts form **three unrelated drawing engines**, each copied from the one before it:

| Engine | Scripts | Look |
|---|---|---|
| PIL at 8x, round caps, `line / arc / circle / poly` helpers | Thresher (the origin), Brittle Star, Shrike, Angler, Starlings, Jacks | filled silhouettes, soft round joins |
| pure-python 1-bit raster (no PIL) | Manta, Butterfly, Stoat, Rhino / Serpent / Scarab placeholders | aliased edges, blobby |
| angular quad strokes, butt caps, mitred joins (`author_objective_icons.py`, which `author_ui_chrome_icons.py` imports) | the objective and UI-chrome glyph sets, **not** any ability icon | line-weight, zero radius, the look `Docs/STYLE_FOUNDATION.md` §5 and §9 ask for |

So the ability row already disagrees with the style foundation on its most basic question (round or
angular), and nothing in the tree can tell: there is no shared primitive library, no icon language
written down for the ROW (the "house icon language" each script cites is one sentence in the
previous script's docstring), no gate that measures legibility, and no step where a sheet is LOOKED
AT before the PNGs are written. `/vessel-model` has all four of those for hulls; that is the gap.

## 2. The audit: what "decent to terrible" is, specifically

Read off the sheet at 128 px and at 40 px. "Reads" means a pilot who has flown the hull once can
name the ability from the icon alone at 60 px.

**Reads (keep as the bar):** Thresher Wrecking Ball / Winch / Plant, Shrike Void Lance / Nest /
Targeting Array, the Starlings' four cards and their three objective glyphs, Jacks Danger Share /
Herd Speed, Stoat Ripple / Field Dipole, Scarab Throttle, Manta Sting, Butterfly Spread Wings.
What they share: ONE focal mass, at most three shapes, a stroke that stays one weight, and the
silhouette fills the optical box.

**Half-reads:** Angler Lure / Seed, Brittle Star Speed Mode / Ring Detonation, Butterfly Fold /
Wingreach, Jacks Breeding / Herding Ring, Shrike Void Sling, Stoat Modes / Pathfinder, Thresher
Mass Mode, Urchin Chain Spikes / Trail Rider. Mostly SCENES: the hull plus the thing plus an arrow,
which is a diagram at 128 px and noise at 40.

**Does not read:** Angler Command (a hull, a beam, a reticle, a fish and a prism row in one box),
Angler Tame (reads as `>=`), Brittle Star Creation / Destruction (scattered squares and hairlines),
Butterfly Scale Dust (blobs), Manta Kabloom (a flower, not an explosion), Manta Yastri (one bent
arrow), Manta Soar (three chevrons - any boost on any hull), Urchin Charge Ring (a bare ring), Urchin
Slip (three circles), Urchin Track Projector (a ladder), and all eleven placeholders (Rhino's three
slashes / double arrow / ramp / lightning, Scarab's ball and ripple and switch, Serpent's reticle /
seed wall / dart).

**The five failure shapes**, each of which the skill has to make structurally hard:

1. **Scene, not symbol.** The icon tries to explain the mechanic instead of naming it. Half the fleet.
2. **Generic.** A ring, an arrow, chevrons, speed lines: true of ten abilities, so it names none.
3. **Hairline detail.** Rays, dots, dashed lines and thin arcs that are 1 px at 60 px and vanish at 40.
4. **No shared weight or box.** Angler's strokes are ~4/128, Manta's blobs ~30/128; some silhouettes
   fill 95 % of the canvas, some 55 %. Next to each other on one HUD they look like four fonts.
5. **Placeholders never leave.** Eleven are two to four weeks old; nothing lists them as owed work.

The artist-drawn HUD icons at the end of the sheet (Sparrow's bullet / fire / missile, Squirrel's
ring cross-sections) are 32-52 px line-weight glyphs: thinner, angular, closer to the style
foundation than anything the scripts produce. They are the "decent" the owner means, and the style
the row should converge on - with the stroke made heavier, because they were drawn for their own
size and 60 px is where the lockup draws everything.

## 3. The skill: `/ability-icon`

Mirror `/vessel-model`'s shape exactly, because that shape is what made the models go up:
**an intention written once, a contract the game binds by name, a pipeline that is one command,
a three-size sheet looked at before anything is written, gates that fire, a critique loop, and a
LESSONS file that every round appends to.**

```
.claude/skills/ability-icon/
  SKILL.md                      the bar, read-before-touch, the pipeline, the loop, the hand-off
  references/
    ICON_LANGUAGE.md            the fleet convention for the ROW (section 4 below) - the intention
    CONTRACT.md                 what the game binds: size, channels, guid, .meta donor, folder .meta,
                                element order, iconBoxSize, the gauge / tint / upgrade-sprite rules
    VOCABULARY.md               the shared pictograms (section 5) with a rendered sheet of each
    LESSONS.md                  seeded from section 2; every round appends what the owner said
Tools/Build/icon_kit/
  __init__.py
  canvas.py                     ONE drawing engine: 128 px, 8x supersample, Lanczos down, the
                                caps / joins the language decides, `stroke`, `fill`, `ring`, `ngon`,
                                `arc`, `arrow`, `cutout` (negative space), boolean ops
  motifs.py                     the vocabulary as functions: hull(), prism(), crystal(), ring(),
                                beam(), trail(), bolt(), burst(), speedlines(), fish() ...
  spec.py                       an icon is a SPEC: name, hull, element, act, a one-line brief, the
                                motif composition; `author_<hull>_icons.py` becomes 40 lines of spec
  verify.py                     the gates (section 6); `--self-test` with negative controls
  sheet.py                      the contact sheet: 128 / 60 / 40 px, tinted with the element colour
                                on the lockup plate (lava blobs and all), beside the hull's other three
  write.py                      PNG + donor .meta with the stable guid, folder .meta, `--check`
```

The existing twelve scripts keep running until each hull's set is re-authored through the kit; a hull
is moved over when its icons are redrawn, never in a bulk rewrite (LESSONS 39 of `/vessel-model`:
one vessel per round, the owner looks at it in the Editor, then the next).

## 4. `ICON_LANGUAGE.md` - the intention (draft to put to Garrett and Shombith)

- **An icon names the ACT in one object.** Not the hull doing it, not the hull and the target and an
  arrow. Test: cover everything but the largest shape; if the ability is gone, the icon is a scene.
- **One focal mass, at most three shapes, no more than four connected components.**
- **Optical box 104 / 128** (12 px margin): the silhouette's bounding box fills at least 80 % of the
  box on its longer axis, and never leaves it. Circular icons are drawn 6 % larger than square ones
  (optical compensation), the only exception.
- **Stroke: primary 11 / 128, secondary 7 / 128, nothing under 6 / 128** (= 5.2 / 3.3 / 2.8 px at
  60 px, and still ≥ 2 px at 40). A gap between two shapes is never under 6 / 128.
- **Angular, zero corner radius, butt caps, mitred joins** - the style foundation's §5 rule, which the
  objective and chrome glyphs already obey and the ability row does not. *This is the one decision
  to confirm before the kit is built*: the Thresher set (the owner's "decent") is round-capped. My
  recommendation is angular, with the Thresher redrawn as the first round's proof, because the HUD
  the row sits on is all slivers and hairlines and the round set reads as borrowed from another game.
- **Filled silhouette first, line-weight for the secondary element** (the gauge fill and the cooldown
  veil sweep over the icon, so a thin-line icon disappears under them; a filled mass survives).
- **Pure white, shape in alpha, no grey** except deliberate 50 % alpha for a "ghost" (the previous
  position, the second mode). Never a baked colour: the card tints by element.
- **Negative space says more than a stroke**: the Starlings' Opposing Mass (prisms cut by an X of
  nothing) is the pattern; a crescent cut out of a disc makes it a sphere, a notch makes a ring a
  reticle.
- **The four of a hull are a FAMILY**: same weight, same box, same vocabulary, and each distinct in
  silhouette from the other three at 40 px (gate 8).
- **Across the fleet, the same thing is the same pictogram** (section 5), so a prism on the Thresher's
  icon is the prism on the Starlings' card.
- **Motion is a shape, not lines**: a swept arc, a displaced ghost, a lean - not three speed lines
  (which every boost in the fleet uses and so says nothing).

## 5. `VOCABULARY.md` - the shared pictograms

Drawn ONCE in `motifs.py`, each with its own rendered tile in the doc so a session can see it:

hull (a side-on chevron with a notch: the generic vessel; a hull's own silhouette is drawn from its
FBX top view by `vessel_model/render_cards.py` and reduced to a 3-shape mark when the icon really is
about THIS hull), prism (the corner-on diamond with one lit face, from the Thresher's `prism()`),
crystal (the four-petal flower already used for Elemental crystals), omnicrystal (the shipped icon),
ring / reticle, beam (a tapering wedge), trail (a chain of diamonds), bolt (Charge), hourglass
(Time), black-hole ring (Space), mass hexagon (Mass) - the Starlings' four already name the elements
and stay the element marks everywhere -, burst (detonation: a ngon with its sides thrown out, the
Brittle Star's), ghost (50 % alpha copy: a previous position, a second mode), lean (a sheared copy:
speed), fish / creature (the Jacks' / Angler's), seed / bulb, chain link, arrowhead (one weight,
one shape; used sparingly, because an arrow is failure shape 2).

## 6. `verify.py` - the gates (every one fires on a committed icon today)

1. 128 x 128, RGB pure white, alpha only; the `.meta` is the house sprite meta with the stable guid.
2. Alpha coverage between 18 % and 45 % of the canvas (below: hairlines; above: a blob).
3. Bounding box inside the 104 px optical box and ≥ 80 % of it on the long axis.
4. **Minimum stroke** by distance transform ≥ 6 / 128 for any component that is ≥ 2 % of the mass
   (`scipy.ndimage` or a pure-numpy erosion; no new package if the sweep can avoid it).
5. **Minimum gap** between shapes ≥ 6 / 128 (the same transform on the inverse).
6. ≤ 4 connected components; no component under 1.5 % of the total mass (specks, rays, dots).
7. **Survives 40 px**: downsample, threshold at 50 %, re-count components and re-measure the bbox;
   losing a component or 15 % of the mass fails.
8. **Distinct within the hull**: the four icons' 24 px binarised masks differ by ≥ 35 % (IoU ≤ 0.65).
9. **No placeholder older than a round**: `*-PLACEHOLDER.png` is listed, dated from git, and the gate
   warns at 14 days and fails at 30 unless the file is on the team board as owed work.
10. `--check` for every hull's spec, like the generators have now; and `check_vessel_class_icons.py`'s
    guid resolution is extended to every `AbilityIconBinding` in every vessel prefab and HUD variant,
    so an icon the row points at always exists (today only the class card icons are checked).

Each gate ships with a negative control in `--self-test` (CLAUDE.md: a gate that aborts looks like a
gate that passes if nobody reads it).

## 7. The pipeline (one command per hull)

```
python3 Tools/Build/icon_kit/author.py <hull>             # spec -> render -> verify -> sheet -> write
python3 Tools/Build/icon_kit/author.py <hull> --check     # drift gate, no writes
python3 Tools/Build/icon_kit/author.py --sheet all        # the whole fleet on one lockup-styled sheet
```

The round, as a skill section:

1. **Brief**: read the class doc (`R_VesselActions/<HULL>.md`), the map asset
   (`Resources/ElementalAbilityMaps/<Hull>.asset`) and `/element-ability-table` for the act, its
   element and its level-5 upgrade; write the one-line brief per icon ("the planted ball as the pivot,
   the hull swinging on it") and the ONE object that names it.
2. **Three thumbnails per icon** in the spec (cheap: the kit renders all twelve on one sheet); pick by
   looking, at 40 px first.
3. **Render, verify, sheet**: the 128 / 60 / 40 sheet on the real lockup plate in the element's colour,
   beside the hull's other three, and beside the fleet's "reads" set from section 2 as the yardstick.
   LOOK at it (Read the PNG) and write down what fails the language before writing anything.
4. **Write** only when every gate is green and the sheet is looked at; commit the spec, the PNGs, the
   metas and the sheet (`Docs/Icons/sheets/<hull>.png`) together.
5. **The owner flies it.** Fold what he says into `LESSONS.md` and `ICON_LANGUAGE.md` before the next
   hull (the `/vessel-model` loop: "prove you can fix one first, then convert your learnings into the
   skill").
6. **Hand-off**: the prefab bindings are already in place for every re-authored hull (same guid); a NEW
   hull's four bindings are written by its `author_<hull>_assets.py`, which the skill names.
